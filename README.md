# Wrench 简体中文汉化补丁

给 Steam 游戏 **Wrench**（Missing Digit，UE4 赛车维修模拟）做的非官方简体中文补丁。
由两部分组成：
1. 往游戏的 `Paks` 文件夹加一个约 18 MB 的补丁包 `zzz_WrenchZhCN_P.pak`：中文翻译表 + 少量改过名字表的资源（应用名、零件名、3D 文字字体）；
2. 把游戏 exe 里少数写死、又不走翻译表的英文**原位替换**成中文（约 40 条）。改之前自动备份原版 exe，卸载时还原。

实测情况：
- **legacy 分支（v145-2830）**：2026-11 在桌面模式下逐项看过——主菜单、设置各页（含按键映射和按键名）、训练关、生涯开场对话、平板全部应用、维修手册（游戏指南全部章节的操作说明、Bauer Catfish 维修步骤）、任务板、车库、商品目录、库存、HUD 按键提示、准星指向零件时的零件名、右键菜单、存档/退出对话框都是中文。
- **默认分支（v162-3615）**：2026-10 用旧方法验证过；改成现在的方法（见原理 5）后还没在 v162 上重新实测。

## 用法

| 文件 | 作用 |
|---|---|
| `一键安装汉化.bat` | `git pull` 检查更新 → 从**你自己的游戏文件**提取文本、生成补丁 → 装进游戏 → 可选直接启动游戏 |
| `卸载汉化.bat` | 删除补丁包、还原原版 exe，恢复英文 |

- 需要 Python 3.8+（bat 会依次找 `py -3`、`%USERPROFILE%\miniconda3`、`anaconda3`、`python`）。
- 游戏路径自动从 Steam 注册表和 `libraryfolders.vdf` 找；找不到就在本文件夹建 `game_path.txt`，写一行游戏目录，例如 `D:\SteamLibrary\steamapps\common\Wrench`。
- 只想要补丁包、不想动 exe：在命令行运行 `一键安装汉化.bat --no-exe`。
- 安装/卸载前请**完全退出游戏**（exe 运行时被占用，改不了）。
- **游戏更新后**重新双击一次安装 bat（Steam 更新会把 exe 换回英文原版，这是正常的）：会按新版本重新提取并生成。新增的、还没翻译的句子会显示英文，并列在 `data/untranslated.json`。
- **切换版本（比如玩 legacy 旧版）**：Steam 库里右键 Wrench → 属性 → 测试版 → 选 `legacy`，等 Steam 下载完，再双击一次安装 bat。补丁总是按**当前装着的版本**重新提取，所以两个版本都能用；切回默认分支后同样要重跑一次。

## 覆盖范围

| 文本来源 | 数量（legacy 版） | 处理方式 |
|---|---|---|
| 资源里的 FText（界面、目录、教程、帮助、故障症状…，三种存法都提取） | 3,626 条 | ✅ 翻译表 locres |
| exe 里的 C++ LOCTEXT 文本（开场教程、任务评价、生涯说明、设置页…） | 1,728 条 | ✅ 翻译表 locres（原理 5） |
| 按键名（鼠标左键、空格键、左 Shift、手柄/VR 手柄按键…） | 350 条 | ✅ 翻译表 locres（F1、Tab、Home 这类键帽上印的字保持原样） |
| 准星指向零件时显示的零件名（FName） | 415 个 | ✅ 改名字表（原理 4） |
| 平板应用名（FName） | 16 个 | ✅ 改名字表（原理 4） |
| exe 里不走 LOCTEXT 的写死字符串 | 约 40 条 | ✅ exe 原位替换（原理 6） |
| VR 手边的零件名标签等 3D 文字所用字体（引擎的 RobotoDistanceField 只有英文字形） | 补 1,375 个中文字形 | ✅ 重建字体贴图（原理 7） |
| 3D 场景里固定的立体字（如 Exit、Start Career 牌子） | 73 处 | 暂时保持英文（原理 7） |
| 品牌/车型/人名（Bauer Catfish、Castrol、Missing Digit…）、包装贴图上的字 | 少量 | ❌ 保持原样 |
| 开发者留的占位文本（`[todo: …]`、`[ETI_…]`） | 少量 | 译成「[待补充：…]」，英文版里本来也是占位 |

## 原理（为什么这样做）

1. **UE4 怎么显示文本**：资源里的每句可翻译文本存成（命名空间, key, 英文原文）。显示时引擎拿 (命名空间, key) 去当前语言的 `Game.locres` 翻译表里查；
   查到了还要比对「原文哈希」（CRC32，按 UTF-32 计算），一致才用译文，不一致就当翻译过期、退回英文。
   → 所以补丁只需要一张 locres，不用改资源本体；游戏更新改了某句英文，那句会**安全地退回英文**而不是乱码或崩溃。
2. **为什么把中文放在 `en` 文件夹**：游戏打包时只带了英文的 ICU 语言数据（`CulturesToStage=en`），切到 `zh-Hans` 会失败、留在英文。
   直接用中文表「冒充」英文表，引擎照常加载 `en`，显示的就是中文。（也同时放了 zh/zh-Hans/zh-CN/ja 几份，作保险。）
3. **补丁包为什么能覆盖**：UE 挂载 pak 时，文件名以 `_P` 结尾的优先级更高，同路径文件以补丁为准。原版 pak 没加密、没压缩（pak v11），所以能直接读，也能用纯 Python 写出引擎认可的 pak。
4. **零件名、平板应用名**：准星指向零件时显示的名字来自零件蓝图的 `PartName`，平板应用名来自 `WrenchOSAppConfigs` 的 `DisplayName`。两者都是 FName 属性（运行时 `FText::FromName`），不走翻译表。
   同一个名字条目常被别处当「标识符」共用（组件变量名、零件路径、故障症状 ID、应用 ID 等），直接改名会让程序找不到东西。
   做法是在资源的名字表**末尾追加**中文名，只把 `PartName` / `DisplayName` 这一个属性指向新条目；原有条目编号和含义都不变，其他用到同一英文名的地方照旧。改好的资源只放在补丁包里，原版文件不动。
   零件名的译文直接复用零件数据表（PartData）里的中文名，保证和商品目录、任务清单里的叫法一致。
5. **exe 里的 C++ 文本，大部分其实能走翻译表**：C++ 里用 `LOCTEXT(Key, "英文")` 写的文本，编译后是固定的指令模式 `lea rdx,[原文]; lea r8,[命名空间]; lea r9,[key]; call 创建文本`（x64 调用约定：第 2~4 个参数在 rdx/r8/r9）。
   `tools/exeloctext.py` 用纯 Python 扫这个模式，把（命名空间, key, 原文）找出来，翻译后写进同一张 locres。好处：完全不用改 exe；同一个英文字面量在别处被当 ID 用也不受影响。
6. **剩下不走 LOCTEXT 的写死字符串，才原位改 exe**：C++ 按「地址」引用字符串常量，所以译文必须放在原地址。中文通常比英文短，写进去后用 0 补齐（字符串只是提前结束）；超长的译文会被跳过、保持英文。
   只替换 `.rdata` 段里**完整**的字符串，不碰部分匹配；凡是在游戏资源名字表（FName）和配置文件里出现过的字符串，都当作「可能是标识符」排除掉（比如按键动作名 `Sprint`，改了会让按键失灵），宁可少翻也不冒险。
   安装时先备份原版 exe（`*.zh_backup`），并记录原版/汉化版的哈希：重复安装总是从干净的原版重新打补丁；检测到 exe 变了（游戏更新、切换版本或 Steam 校验）就把新 exe 当作新原版。
7. **中文字形**：界面用的 Roboto 字体带 DroidSansFallback 作后备，中文能正常显示，不用额外打字体。
   但 3D 文字（TextRenderComponent，比如 VR 里手边显示的零件名）只能用预先烘焙的「离线字体」：一张距离场贴图 + 每个字的矩形表。
   引擎默认的 `RobotoDistanceField` 只有 256 个拉丁字形（512×256），中文就成了方框。
   `tools/dffont.py` 重建这个字体：新贴图 4096×2048，原来的拉丁字形放大 2 倍搬过去（距离场放大不糊），再加上用引擎自带 DroidSansFallback 渲染的中文距离场字形（`data/cjk_glyphs.bin`，由 `tools/make_cjk_glyphs.py` 生成）；
   字表改成 `IsRemapped` + `CharRemap`（UTF-16 码位 → 字形序号）。所有字形同样 52 像素高，所以字在场景里的大小不变。
   场景里固定的立体字牌子和界面有时共用同一条文本 key，目前仍把它们的 key 改掉一位让它们查到英文（长度不变、别的字节不动）。
8. **帮助页里的 `{WGKEYIMG(...)}`**：这是开发者预留、但游戏里没有实现的按键图标占位符，英文版也是原样显示。中文译文直接写成可读的按键提示（如「使用【空格键】和【C】升高或降低站立高度」）。

## 依赖的假设 / 什么情况下会失效

- pak 保持「不加密、不压缩、v10/v11 带完整目录索引」。如果开发者改成加密 pak 或 IoStore（.utoc/.ucas），提取器会报错。
- 文本仍用 UE 标准本地化文本。如果之后改用 StringTable，或新增不走 LOCTEXT 的写死文本，那些会显示英文。
- LOCTEXT 提取依赖 MSVC 生成的 `lea rdx/r8/r9 + call` 指令模式。换编译器或大改优化选项后可能识别率下降（构建时会打印识别到的条数，骤降就说明这里出了问题）。
- exe 补丁基于「完整字符串内容」匹配，不依赖地址，所以游戏更新后重跑 bat 仍有效；新增的写死文本会是英文，可用 `python tools/extract_exe.py` 列出来补翻。
- 零件名改的是零件资源里的名字表。已检查过：这 415 个中文名只被各自零件的 `PartName` 引用，其余同名的英文条目（组件变量、零件路径、故障症状 ID）都没动。
  仍有一个没法从文件上排除的小风险：如果游戏代码或存档拿 `PartName` 去做比较，可能出现异常（实测零件名显示正常，但没跑完整的拆装维修流程）。遇到问题先运行卸载 bat 对比。
- 如果 exe 补丁导致异常：运行卸载 bat，或在 Steam 里「验证游戏文件完整性」即可恢复原版 exe。
- `WrenchOSAppConfigs` 或零件资源结构变了时，构建会自动**跳过**应用名/零件名这一步（打印提示），其余照常。
- 翻译是 AI 机翻 + 术语表约束，难免有不地道的地方，欢迎直接改 `data/zh_CN.json`（英文原文 → 中文），改完重跑安装 bat。
  同一个英文词在不同地方要不同译法时（比如 "Empty" 作状态是「空」，作按钮是「清空」），在 `data/zh_context.json` 里写 `"资源名|英文": "中文"`。

## 文件结构

```
一键安装汉化.bat / 卸载汉化.bat
data/zh_CN.json        资源文本：英文原文 → 中文（可手改）
data/zh_context.json   个别资源里的特殊译法："资源名|英文" → 中文
data/zh_exe.json       exe 里的 C++ 文本：英文 → 中文（原位替换的那部分译文不能比英文长）
data/zh_inputkeys.json 按键名：引擎按键 ID → 中文
data/glossary.md       术语表
tools/build.py         入口：提取 → 生成 locres → 打 pak → 安装/卸载
tools/extract.py       从游戏 pak 提取 FText（GUID key / 可读 key / 蓝图字节码三种格式）
tools/exeloctext.py    从 exe 里识别 C++ LOCTEXT 文本（纯 Python，无需反汇编器）
tools/locres.py        写 UE4 .locres（legacy 格式）
tools/pakfile.py       纯 Python 读写 UE4 pak v11（无压缩、无加密）
tools/uasset.py        解析/改写 uasset 包头、名字表、导出表
tools/appnames.py      平板应用名汉化
tools/partnames.py     零件名汉化
tools/textrender.py    让场景里固定的 3D 立体字保持英文
tools/dffont.py        给 3D 文字字体补中文字形
tools/make_cjk_glyphs.py 维护用：渲染中文距离场字形（需 Pillow、numpy、scipy）
data/cjk_glyphs.bin    中文距离场字形（源自 DroidSansFallback，Apache 2.0）
tools/idents.py        收集「可能是标识符」的字符串，exe 原位替换时避开
tools/exepatch.py      exe 原位替换（备份/还原/哈希状态）
tools/extract_exe.py   维护用：列出 exe 里还没翻译的文本
```
